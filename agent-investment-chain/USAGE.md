# 使用方式和落地路线

## 1. 给任意智能体的启动提示词

把本目录放入项目上下文后，对 Codex、Claude Code、Cursor 等智能体输入：

```text
请读取 agent-investment-chain/MASTER_PROMPT.md、WORKFLOW.md、AGENTS.md、
DATA_SOURCES_A_SHARE.md、SIGNAL_POLICY.md。

你现在是 A 股智能投研助手。请针对 {股票代码和名称} 做动态投研分析。
我的投资周期是 {短线/波段/中线/长线}，风险偏好是 {保守/平衡/进取}，
账户总资金 {金额}，单票最大仓位 {比例}，单笔最大亏损 {比例}，
当前持仓 {数量/成本/无持仓}。

请按 templates/stock_report.md 输出报告，并按 schemas/signal.schema.json 输出条件化提醒。
没有数据时不要编造，必须列出需要补充的数据。
```

## 2. 单股分析流程

推荐每次分析分三步：

1. `建立档案`：读取股票基础信息、行业、财务、行情、公告和交易状态。
2. `生成报告`：按模板输出完整投研报告、反方报告和关键价位。
3. `生成信号`：只在数据、回测和风控都满足时输出条件化提醒。

示例：

```text
请分析 300750.SZ 宁德时代，周期为波段，风险偏好平衡。
我当前无持仓，账户 100000 元，单票最大 15%，单笔最大亏损 1%。
请输出完整报告、反方报告、支撑阻力位、候选建仓条件和止盈止损计划。
```

## 3. 盘前/盘中/盘后任务

### 盘前

```text
请根据 watchlist.example.yaml 的股票池做盘前检查。
重点检查公告、业绩预告、政策、热点、外围市场和今日触发价。
只输出发生变化的股票和需要关注的触发条件。
```

### 盘中

```text
请做盘中触发检查。
不要重写长期基本面，只检查价格、成交额、涨跌停、支撑阻力、止损和止盈触发。
输出是否触发 watch、pilot_build、add、take_profit_partial、stop_loss。
```

### 盘后

```text
请做盘后复盘。
更新 K 线、成交额、换手、龙虎榜、融资融券、行业相对强弱。
说明哪些结论改变，哪些信号失效，明天需要观察哪些价位。
```

## 4. 最小可用版本

第一阶段先不接实盘交易，只做研究和提醒。

### Phase 1：手动数据 + Agent 报告

- 手动提供股票代码、当前价、财报关键指标、最近公告和 K 线截图/行情数据。
- Agent 按模板输出报告和信号。
- 适合验证分析框架是否符合你的投资风格。

### Phase 2：自动数据采集

- 用 AKShare 或 Tushare 拉日线、财报、公告、行业和资金数据。
- 保存到 DuckDB/Parquet。
- Agent 只读取结构化数据和原始证据链接。

### Phase 3：技术指标和支撑阻力自动计算

- 自动计算 MA、MACD、RSI、KDJ、BOLL、ATR、成交额分位。
- 自动识别前高/前低、缺口、箱体、成交密集区。
- 输出候选触发价和失效价。

### Phase 4：回测

- 用 vectorbt 快速验证技术规则。
- 用 Qlib 验证因子和行业轮动。
- 用 Backtrader 验证事件驱动和更复杂的交易规则。
- 回测结果进入 `backtest_score`，不通过则不能升级为建仓/加仓提醒。

### Phase 5：告警和复盘

- 定时运行盘前、盘中、盘后任务。
- 告警渠道可以是本地 Markdown、邮件、企业微信、钉钉或 Telegram。
- 每条提醒都写入复盘表，记录触发、执行、结果和失败原因。

### Phase 6：模拟盘

- 只在提醒系统稳定后接模拟盘。
- 验证滑点、涨跌停无法成交、T+1 和仓位控制。
- 模拟盘稳定前不要接实盘。

## 6. 判断“可以提醒建仓”的最低标准

至少满足：

- 没有禁入条件。
- 基本面不是明显恶化。
- 热点或产业链逻辑有真实业务敞口。
- 技术面出现明确触发位置。
- 止损位明确，且单笔亏损不超过预算。
- 回测不是负期望。
- 反方报告没有发现足以推翻交易的证据。

不满足任何一项时，输出 `watch` 或 `no_trade`。

## 7. 下一步建议

建议先选 5-10 只你熟悉的 A 股建立观察池，用 Phase 1 跑 2 周，检查报告质量和信号稳定性。确认框架适合后，再接 AKShare/Tushare 和 vectorbt。
